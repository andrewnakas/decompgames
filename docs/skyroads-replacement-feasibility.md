# SkyRoads clean replacement feasibility (experimental)

Pinned upstream: [`haroldo-ok/skyroads-32x@df219e03b854153291b32224593013b60d861d40`](https://github.com/haroldo-ok/skyroads-32x/tree/df219e03b854153291b32224593013b60d861d40). Its README documents disassembly-based C reconstruction, MIT source license, and Emscripten support. Its game data remains Bluemoon's, outside that license. The upstream Web recipe bundles whichever original files are present; it is **not** eligible to deploy as-is.

## Independent course-data experiment

`scripts/build-open-skyroads-roads.py` generates `ROADS.LZS` from authored geometry and palettes without reading any retail file. It writes a 31-entry directory (one demo course and thirty selectable courses), each with 7-column tile rows, center-safe path, supplies/boosts/shoulder obstacles, and seven tunnel-gate rows. The generator records per-road grid hashes, archive SHA-256, size, format revision, and CC0 provenance in a sidecar JSON. These are experimental layouts, not yet tested in gameplay or claimed as a finished replacement campaign.

Run `python scripts/build-open-skyroads-roads.py .cache/open-skyroads-roads/ROADS.LZS`. This produced a 35,134-byte archive, SHA-256 `a5249198fdd6ccec9d7a8eb70ed3fabcdbddb41a135f43790bc78753e6c132c4`. A second independent invocation produced the same digest. All 31 entries were decoded with the **pinned upstream** `tools/lzs.py` reader; each decompressed to exactly its directory size, had six-bit palette channels and 7-column rows, kept the center nonempty, and ended with seven all-tunnel rows. This validates the wire format and authored content, **not** a playable race or course completion. The generated file is kept in ignored `.cache/`, never uploaded to production.

## Full replacement boundary

The pinned `CMakeLists.txt` lists **27 original-data paths**: 17 base files and `WORLD0.LZS` through `WORLD9.LZS`. `src/core/assets.c` requires seven graphics containers (`MAINMENU`, `SETMENU`, `HELPMENU`, `GOMENU`, `INTRO`, `CARS`, `DASHBRD`), `TREKDAT.LZS`, `OXY_DISP.DAT`, `FUL_DISP.DAT`, `SPEED.DAT`, `DEMO.REC`, `ANIM.LZS`, and `INTRO.SND` at boot. Later play reads `ROADS.LZS` and a world backdrop. The separate audio path reads `MUZAX.LZS` and `SFX.SND`; a release variant must disable or replace its SDL audio device and these reads so browser testing stays silent. None of those missing files can be copied from the upstream browser build.

Menu drawing indexes at least three `MAINMENU` pictures, six `SETMENU` pictures, multiple `HELPMENU` pictures, and two `GOMENU` pictures. Gameplay uses the first 24×2310 `CARS` strip, first `DASHBRD` and world pictures, ten gauge records in each gauge file, speedometer records, and at least eight `TREKDAT` objects. `TREKDAT`'s second-stage expansion in `src/core/render.c` has a 0x270-byte directory and bespoke span records, a larger replacement-art task than the road format. `docs/FORMATS.md` explicitly labels some sprite, object, speedometer, demo, and sound details as unfinished; treat those as blockers until validated.

The remaining data and null-audio build are documented below. This candidate is still **not** addition 4/5.

## Independent graphics-container experiment

`scripts/build-open-skyroads-visuals.py` now writes **17 independent graphics containers**: intro, three-state main menu, settings, three help screens, thirty-road chooser, 77-frame spacecraft strip, dashboard, and ten world backdrops. It draws geometric pixel art and a hand-authored five-pixel font into the documented `CMAP`/`PICT`/LZS format with only 6-bit palette channels. No original file is read. The generator uses Pillow 12.3.0 for primitive drawing; the font and visual content are defined in the script. Its sidecar manifest records CC0 intent, sizes, and SHA-256 hashes.

The pinned upstream `tools/extract.py` and `tools/lzs.py` decoded all 17 generated containers. Picture counts matched the C renderer's indexed expectations (main menu 3, settings 6, help 3, go menu 2; the other files have one picture each). The generated intro and road chooser were visually inspected; their independent text and geometry are legible. These are format and static-art checks only. The engine has **not** rendered them, and frame alignment, gameplay spacecraft animation, HUD function, and full-game art quality remain unverified. The generated files remain in ignored `.cache/` and were not deployed.

At this stage, the generators covered 18 of 27 original-data path names. The remaining nine were `ANIM.LZS`, `DEMO.REC`, `FUL_DISP.DAT`, `OXY_DISP.DAT`, `SPEED.DAT`, `TREKDAT.LZS`, `INTRO.SND`, `MUZAX.LZS`, and `SFX.SND`.

## Independent support-data and null-audio staging experiment

`scripts/build-open-skyroads-support.py` now generates seven of those nine files without original input: an `ANIM` intro frame, inert `DEMO.REC` input, ten oxygen and ten fuel HUD segments, 34 speedometer segments, eight new `TREKDAT` perspective objects, and a one-byte placeholder intro sample that the null-audio shell cannot play. `MUZAX.LZS` and `SFX.SND` are intentionally absent. The pinned upstream LZS decoder accepted all eight `TREKDAT` objects; a second-stage check expanded each 0x270-byte directory and its 1,040 span records to the declared raw size, with directory offsets and drawn spans inside the framebuffer. The pinned animation decoder accepted the independent intro frame, and all HUD record offsets and on-screen bounds passed format checks. These checks do **not** establish correct in-engine rendering, useful depth cues, or a completed course.

`scripts/build-open-skyroads-browser.py` stages **only** the pinned engine's C source, CMake recipe, license, and 25 explicitly named generated data files. It rejects any missing, duplicate, empty, or unexpected file and writes a SHA-256 build-input record. The staged SDL shell removes `SDL_OpenAudioDevice` and `SDL_PauseAudioDevice` entirely and retitles the window Open Skyways. Local `--prepare-only` staging passed with all 25 files and no audio-device calls; binaries compile in private CI, not on this Windows host. The private [experiment workflow](../.github/workflows/open-skyroads-experiment.yml) pins Pillow 12.3.0 and Emscripten 6.0.1, compiles off-site CI, checks the replacement hashes and no-audio source, and retains the artifact for one day. It does **not** deploy or claim a released game.

## Private muted browser probe, September 27

[Private CI run 36289640742](https://github.com/andrewnakas/decompgames/actions/runs/36289640742) passed and produced the first unmodified experimental browser artifact. The one-day artifact remains private and was not deployed.

`scripts/test-open-skyroads-private.mjs` launched that artifact on a local server in headless Edge with `--mute-audio`, blocked non-local requests, and closed the player and server. Visual screenshots confirmed the title, main menu, thirty-road chooser, rendered road/HUD, and a **Road Completed** result after holding accelerate on Road 01. This is a real silent completed-course observation, though it covers only one generated course. The minimalist road art disappears after the ship reaches the finish; visual polish and steering remain to inspect. The test made no persistence assertion. The browser build still cannot count toward the milestone.

That first build had no persistent storage; the following revision added IndexedDB. Controls, save guidance, provenance, final checksums, and production deployment/test remain release gates.

## Private persistence build and retest, September 27

Commit `6b81dc6` compiled in [private CI run 36292532444](https://github.com/andrewnakas/decompgames/actions/runs/36292532444). It uses the same 25 generated data inputs, mounts IDBFS `/save` before `main`, reads config there first, writes config there first, and synchronizes writes to IndexedDB. SDL initializes only video and never opens an audio device. Build hashes: `skyroads.html` (19,603 bytes) `a2b371d289c251568c116dc0d36441939f5701c13a892c14237c941975e22d38`; `skyroads.js` (180,578 bytes) `db4d0d3795c5ce4d8a3e4a429e4da9f53b101049c9aa885bab1add8666476931`; `skyroads.wasm` (685,541 bytes) `d28ac44c6abf4188a575a119917a5d31909efe330c9f4d6bf190c79b83cc7cd3`; `skyroads.data` (1,402,541 bytes) `59b1a2a61bd46d813f5f7f8d5763c4c6ada53137ee865bf89cb08ccd0e5b3f37`. The artifact remains private and was not deployed.

The muted Edge probe again reached Road 01 and displayed **Road Completed** after held acceleration. An IndexedDB `FILE_DATA` record contained a 66-byte `skyroads.cfg` with Road 01's completion count equal to 1. After a page reload and return to the road chooser, the completion marker remained visible. This supports a first-course loop and reload persistence in that local browser profile. It does not establish all 30 generated roads or steering/jump quality. Road art was sparse, especially once the ship passed the finish; improve and inspect it before release. The scripts and test screenshots are local; this candidate remains uncounted until the full release gate and production test pass.

The later package `df219e03b854-59b1a2a61bd4` exposed browser FS for site backup controls and coordinated its own private IDBFS mount with the site's namespaced save mount. The first local site integration exposed a missing `Module.FS` export, and a second exposed an IDBFS namespace conflict; both were fixed in the pinned recipe. The final local site test completed Road 01, exported a verified one-completion config, deleted it, then imported it and visually restored the marker. Right steering and Space jump visibly moved the ship. The exact production package subsequently passed the same silent course-completion and backup-restoration gate; downloaded files matched all manifest hashes. Exact build/source hashes, provenance, controls, and the limited test record are in [Open Skyways integration](open-skyways-integration.md). Open Skyways is verified addition 4/5; the other 29 roads remain untested.
