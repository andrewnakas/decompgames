# Tube replacement-data feasibility (research, not a release)

Upstream: [`rep-stosw/tube-game-dos` at `d2c74cdbb82fedacc528f651ef28820bd186e0d2`](https://github.com/rep-stosw/tube-game-dos/tree/d2c74cdbb82fedacc528f651ef28820bd186e0d2). Its README documents a Hex-Rays/IDA reconstruction of the 1994 DOS game and an Emscripten target. The repository declares GPL-2.0 for its source. None of its included original-game data is approved for Decomp Games redistribution. This note uses filenames, code paths, and file lengths to size a possible independent replacement; it does not derive art or levels from the original bytes.

The pinned `TubePCWEB/build_web.bat` copies `bin/DSEG3.bin`, `DSEG4.bin`, all of `bin/DATA`, and `SOUND` `.TAB`, `.BNK`, and `.DAT` files into `asset/`, then preloads the directory into the WebAssembly build. Its existing browser package therefore fails the replacement-asset gate even though the source compiles for Web. `Game/misc.cpp::LoadDSEG()` reads both segments before gameplay and rebinds startup-file destinations, animation order pointers, palette, high-score, block, logo, and screen state into `DSEG3`. The segments are 624,880 and 1,296 bytes. They are not optional artwork that can simply be omitted.

The external data inventory includes four 66,136-byte `LEV*.DAT` levels, `TUNNEL.DAT` (131,072 bytes; `tube.cpp` checks this exact length), `BLOCKS.DAT` (131,072), `GLASS.DAT` (65,536), two 65,536-byte texture files, 3D points/faces/objects, palette, logo data/index, tables, and score data. `tube.cpp::CPP_load_level()` accepts a level only when the read returns exactly 66,136 bytes. The pinned sound code reads `S822-0.TAB/.DAT`, instrument banks, and `MUSICF-0.TAB/.DAT`; a silent replacement would need to bypass these sound loaders and retain gameplay timing without audible output. This is a file-format and source-path inventory, not permission to reuse any file contents.

An eligible Open Tube edition would need: (1) map the live `DSEG3`/`DSEG4` fields and distinguish engine state from original presentation/content; (2) generate independent segment initialization and every required data file in accepted formats, including a complete level loop; (3) remove or null the sound loaders; (4) pin a browser build without upstream `bin/` assets; and (5) complete silent launch, input, representative gameplay, level completion, and save checks. Until those are done, Tube is a longer-term candidate and **0 counted releases**. `tube64` is a port of the same game, not a second candidate.
