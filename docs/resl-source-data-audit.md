The top-level upstream `resources/` directory is excluded from the private build; only generated external files are embedded. A source-wide search for static byte arrays found the SDL cursor outside `src/game/resources`; other matches reviewed so far were control, text, audio, or rendering logic. Re-run this audit after source changes and before distribution. Do not infer that an exhaustive asset clearance has already happened.

A September 23 follow-up inspected the remaining small tables in the pinned `src/game/resources` directory. `rail_connection_bias`, `rail_connection_rule`, and `rail_type_meta` map rail ports, neighbors, and signal rules; they do not encode pictures or level placement. `movement_paths` contains per-rail motion coordinates used by routing and collision checks. `carriage_bias` and `semaphore_glyph_bias` are sprite-alignment offsets coupled to the new drawings. The private recipe now replaces both offsets using the dimensions of its independent vehicle and signal sprites. The other four tables remain GPL engine geometry. Visual effects still need broader dynamic checks; this classification does not clear the whole source tree.

The private build recipe now compares the entire pinned `src/game/resources/*.cpp` inventory with explicit sets of eleven independently replaced glyph and signal-alignment tables, six independently replaced scenario and vehicle-alignment tables, and four retained engine-geometry tables. It fails if an unclassified table appears and records sizes and SHA-256 hashes for the retained four. This is a reproducible inventory guard; it does not substitute for a whole-source provenance review. The signal table preserves port orientation required by engine rules while its placement distances are chosen for the replacement mast.

The source copy used for the browser build is now allowlisted to `src/`, `CMakeLists.txt`, `LICENSE`, and `README.md`; it omits the upstream top-level original game data, Android/iOS launcher art, and executable-extraction utilities under `src/game/resources/scripts` and `utility`. Only generated `resources/open-junction` files are added back. The narrowed copy compiled and its archive inventory passed in [private CI run 35903723403](https://github.com/andrewnakas/decompgames/actions/runs/35903723403). Final whole-source provenance review remains open.

`scripts/package-open-junction-private-source.py` now checks the build-record hashes, the allowlisted source roots, and the generated-resource boundary before creating a deterministic private source archive. The CI job checks that the patched text source and generated `play.7` are present. It neither uploads this archive nor distributes the runtime; this packages evidence for review without claiming the remaining asset audit is complete.

The first gameplay screenshot also exposed an inherited original-game footer and a grass routine that scattered original-style presentation pixels. The private recipe now substitutes an Open Junction source credit, uses a clear drafted grid, and retains the independently generated trees and houses. The updated frame is legible at the intended 640×480 SDL size; tree density and numeric counters still need review. The screenshot artifact is temporary and contains no engine binary.

The candidate build is still private. Muted browser tests establish menu input, entry to the gameplay loop, player-built rails, train dispatch and movement, and completed deliveries on the initial two-station route. A trace-targeted service from station 2 to a newly added station 3 also arrived after player-built branch rails and a player-operated switch; this is connectivity evidence, not ordinary multi-station traffic. The independently drafted scenario starts with three connecting rails between the first two stations. A private browser Save, page reload, and Archive restore passed using the engine's IDBFS mount. The actual shared player passed export/delete/import controls and resumed its saved two-station game through Archive in an ephemeral preview. A trace-only probe reached the year-2000 level-transition branch and reset to year 1800 at level 2; it does not establish continuous play through 200 years. Release still requires organic wider traffic, broader visual review, scenario/game-over coverage, and final provenance review. It remains outside the five-release count.

Subsequent [private run 35967151896](https://github.com/andrewnakas/decompgames/actions/runs/35967151896) added one scheduler-spawned 2→1 arrival after a player-operated junction change, so ordinary three-station dispatch now has one confirmed successful journey. The same run retained a second active train at observation end. This advances gameplay evidence but does not clear the remaining source-data, dynamic rendering, and longer-run issues; no runtime or source archive was published.

A source-wide inventory of the pinned `src/` tree found only C/C++ files once upstream extraction scripts are excluded. Outside `src/game/resources`, five byte-array definitions remain: two original cursor bitplanes and the original font-spacing classes (all replaced by the private recipe), plus a transient per-train state array and a DOS keycode translation table (engine logic/input data). Other inspected static arrays are generic month names, menu button labels, route math, or runtime filename constants. Literal game-data reads are limited to `play.7`, `poster.7`, `captions.7`, `GAMEOVER.7`, and `RULES.TXT`, all generated independently; records and save files use dynamic names. The recipe now fails on any new source-tree file type, non-resource byte array, or literal resource read. This narrows the remaining provenance review to the four retained engine-geometry tables and the presentation of dynamic drawing code; it does not by itself prove the published build is ready.

The latest replacement-only CI screenshots were visually inspected at native 640×480 and in the shared player: header numerals are legible, the board grid survives the third-station redraw, the train and its route appear without visible leftover sprite fragments, the Pause dialog opens, and the player starts with **Sound: off**. The footer credit and smaller labels are thin at native size, and one static train frame cannot prove every switch/signal/redraw state. Dynamic visual coverage and long-run conflicting traffic remain release checks.
