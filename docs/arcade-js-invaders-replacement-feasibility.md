# Space Invaders translation: independent-data feasibility

Research revision: [`qarl/arcade-js` `e849d086f4168c9a0e1ab501d62efbe3766def8a`](https://github.com/qarl/arcade-js/tree/e849d086f4168c9a0e1ab501d62efbe3766def8a). The upstream repository is GPL-3.0. Its `games/invaders/manifest.js` declares a browser frontend and an idiomatic JavaScript translation of the 8080 program, but also requires a byte-exact 8,192-byte original program ROM. `boards/invaders/memory.js` maps reads at `0x0000`–`0x1fff` to that ROM. We have not loaded original ROM bytes, created a replacement pack, or play-tested an independent build.

The translated functions do **not** make the ROM dispensable. The upstream `games/invaders/idiomatic/names.js` labels data addresses in it, including fleet speed and shot-rate tables (`0x1a11`, `0x1a21`, `0x1aa1`), work-RAM and object templates (`0x1b00` onward), alien and explosion sprite bitmaps (`0x1c00` onward), shield and score data (`0x1d20` onward), glyph bitmaps (`0x1e00`), and attract, coin, credit, and game-over text in the upper part of the image. The board has no separate graphics ROM; it paints a one-bit framebuffer from this data. The existing sound map refers to visitor-supplied original-game samples, so an independent silent build must omit those samples and default to no audio.

An eligible Decomp Games adaptation would need to:

1. Inventory every runtime read of the 8 KiB image, including indirect reads and any translated fallback, without copying bytes from a game ROM.
2. Author original sprite and glyph bitmaps, text, shields, templates, and gameplay/balance tables in the expected formats. Generate a deterministic 8 KiB **new** data image and record the source, license, and SHA-256 for each input and the output.
3. Give that new image a distinct manifest and checksum. The upstream hash is an original-ROM identity check, not a license to mirror its contents; do not relabel a modified image as the original set.
4. Test a muted real browser session from attract/start through movement, fire, alien hits, wave transition, loss, and restart, then document persistence if the adaptation supports it. A rendered title or a few moving pixels would not count as a complete playable game.

This is a candidate scope, not a release. Its original-game title and visual identity should be replaced for the independently authored edition; the upstream historical project remains credited for the GPL translation.

`scripts/audit-arcade-js-invaders-feasibility.mjs` now pins that exact checkout revision and traces ROM reads during 200 frames with an all-zero 8 KiB placeholder. It loads no original ROM and produces no audio. The run reached its frame limit without an exception, but `ATTRACT_DEMO_PTR` and `GAME_ACTIVE` both remained zero: it did **not** enter a proven attract sequence or a game. It touched 328 ROM addresses, including `0x1ae4`–`0x1bff`, several text records, and two 8-byte glyph slices. This dynamic list is path-dependent and incomplete because all-zero tables suppress normal branches. It demonstrates that even startup reads substantial data; it is not evidence that the translated logic can play with blank assets. The next useful step is to specify each live template and script format, generate independent data, then rerun the trace through an actual game loop.

A first **incomplete** Open Swarm data-format draft is generated by `scripts/generate-open-swarm-data.py`. It reuses our CC0 drafting glyph shapes, packs them into the documented 8-byte-per-glyph table at `0x1e00`, and adds independently written score and credit labels. The 8,192-byte draft has SHA-256 `6f331eafccf67111bc13596fc0dd3e139608991110a7db36a090ee6480ac6971`. Its manifest explicitly lists missing gameplay templates, alien/ship sprites, balance tables, shields, and attract/game-over scripts. The pinned headless trace with this data reached 200 frames and wrote 210 nonzero framebuffer bytes, compared with zero for the blank placeholder; `ATTRACT_DEMO_PTR` and `GAME_ACTIVE` still remained zero. This is a narrow rendering/data-format advance only. No game can be played from this image, and it must stay off the public site until a complete independent pack passes browser gameplay tests.

September 27 probe update: the generator now also writes six original 16-byte fleet silhouettes at `0x1c00`–`0x1c5f`, a 16-byte reserve craft at `0x1c60`, 32 bytes of explosion frames at `0x1c70`, and an original 44-byte arch-shaped shield template at `0x1d20`. These sizes and read locations follow the translated engine's `drawPendingAlien`, `drawReserveLifeIcons`, and `initShieldBuffers` routines; the shapes are new CC0 work. Regeneration produced SHA-256 `0cbdff079ba5dd878bcaf19b630889c6f038f74b218208dfe0ef9d57ff367dbf`. A silent 200-frame headless trace at pinned revision `e849d086f4168c9a0e1ab501d62efbe3766def8a` terminated without an exception and observed 448 distinct ROM-address reads and 210 nonzero framebuffer bytes, but still reported `ATTRACT_DEMO_PTR=0` and `GAME_ACTIVE=0`. The new art has therefore **not** been exercised as a gameplay render. Work-RAM/object templates and scripts remain the likely immediate boot blocker; this probe is not eligible for hosting or milestone credit.

The subsequent 1,000-frame probe exposed a concrete data-format failure: a zeroed `0x1dbe` draw-script terminator caused `drawScoreAdvanceTable` to walk nearly the whole 8 KiB image (`7,909` distinct addresses) instead of stopping. Independent `0xff` terminators at `0x1dbe` and `0x1dcf` reduced that to `483` addresses and let the attract sequence reach its animation task. Three independently specified one-tick transition records at `0x1a95`, `0x1bb0`, and `0x1fc9` then let the sequence initialize four shield buffers; the trace read the entire 44-byte authored shield template four times. Finally setting the round-armed state byte in the new work-RAM image (`0x1b15=0xff`, copied to `0x2015`) made `ATTRACT_DEMO_PTR` advance from zero to one. The current draft image SHA-256 is `e3ad7c18e12ff04e4e8745d12f8d55095ad930f0fa38e701e7dac20ae18df029`. At frame 1,000 it still has `GAME_ACTIVE=0`, `TASK_FLAGS=1`, and no demonstrated controllable loop: the remaining object and shot records are blank, so the demo stalls after its first step. The blank transitions are a format probe, not completed replacement animation or gameplay. No public package was built or deployed.

Later September 27 data-format probe: the generated image now seeds five translated object-handler addresses, a terminating sixth record, a video-safe original ship descriptor, and an original shot beam/descriptor. A zeroed ship descriptor previously wrote into work RAM during object dispatch and erased the record terminator; the safe descriptor avoids that failure. A coin at frames 300–305 and Start at frames 360–365 now traverse the 176-frame round splash. The player-page selector in the template must contain **`0x21`**, the high address byte for the `0x2100` alien field, rather than ordinal `1`; `1` made the foreground count zero aliens and repeatedly enter the next-round delay. With `0x21`, the headless translated engine first reports a live 55-alien field at frame 537. At 1,200 frames, simulated left, right, and fire input changes the ship X coordinate from its idle value 96 across 48–108 and produces 276 frames with a nonzero shot-status byte, compared with X=96 and zero shot-status frames on the coin/start-only baseline. The 8,192-byte independent draft SHA-256 is `707de8f7a27e1e59a809ffa6d3d31756cf52cbb5e88db164bd8d6fa7e981c62a`.

This remains an **incomplete headless feasibility probe**, not a browser gameplay test or a releasable game. The field remains at 55 aliens in the probed interval; no hit, wave completion, loss/restart, or persistence has been shown. The secondary alien-shot and saucer records remain disabled, and balance tables, complete animation/score scripts, safe remaining descriptors, and browser packaging are unfinished. Sound output was not attached or tested. Keep the draft off the site and out of the five-release count.

Further September 27 stress probe: the independent shot template now has a 16-frame retirement timer (zero underflowed to a 256-frame stall), and the invader-hit explosion descriptor points at the authored art with a bounded 16-row blit. The current draft SHA-256 is `366591003d2e2c7264619fe9118c1cf85070caf52ecdfe427a2e536e5f673cad`. Repeated fire from a fixed X left 41 of 55 aliens after 10,000 headless frames; no wave completion. A faster sweep/fire input script killed 39, leaving 16, but at frame 6,401 an alien blit used packed coordinate `0x0098`. That maps to work-RAM address `0x2013` and overwrote the ship-handler target `0x028e` with `0x001a`, causing a deliberate unknown-handler exception. This is a concrete **unsafe fleet-coordinate boundary** in the incomplete data/translated behavior, not a verified game loss or successful loop. The fleet edge/turn data and rendering bounds must be resolved before any browser packaging, let alone release.

The pinned edge-scan trace narrows that blocker: `reverseFleetAtEdge` checks video bytes at `0x2524` and `0x3ea4`. At frame 1,820 only the right edge was lit; by frame 1,821 **both** edge scans were lit. The heading then alternated left/right on successive frames (step byte `0xfe`/`0x02`), while already-drawn pixels remained at both edges. The fleet eventually produced column coordinate zero and wrote into the object table. Narrowing all six independently drawn alien frames to central bit columns delayed the exception to frame 8,419 but did not fix it, so that art experiment was reverted. It remains to determine whether the translated edge check needs a scoped browser-port fix, whether the authored art/field setup causes persistent edge pixels, or both. No production runtime was changed.

Experimental **source patch, not a release**: [`patches/arcade-js/edge-clear.patch`](../patches/arcade-js/edge-clear.patch) (SHA-256 `e1242a57f67d90444be041d9a5f1ea5b6f994b0934bd828f9311e7e73153aad7`) changes the GPL translated edge-turn routine to clear only the 23-byte video probe strip just departed. It applies cleanly to upstream `e849d086f4168c9a0e1ab501d62efbe3766def8a`. This removes the persistent opposite-edge signal without altering the fleet's direction or step decision on the current frame. With the unchanged independent draft image (`366591003d2e2c7264619fe9118c1cf85070caf52ecdfe427a2e536e5f673cad`), **no frame-hook edge mutation**, and silent synthetic control inputs, the patched headless engine reached the next wave at frame 13,634, returned to game over at 15,355, accepted a new coin/Start, and entered a second play session at 15,661. It ran to 20,000 frames without an exception. That demonstrates a complete wave and restart in the patched headless probe only. The edge-strip erasure changes translated rendering behavior and still needs careful real-browser visual and gameplay review; alien-shot/saucer replacement records, complete text/balance data, packaging, controls/save guidance, and the browser release gate remain undone. It stays uncounted and unpublished.

The probe validates the source patch and generated data checksums before running. No sound player or web server is involved.

September 27 **private browser integration probe**: `experiments/open-swarm-browser-probe.html` accepts only the generated 8,192-byte independent image whose SHA-256 is `366591003d2e2c7264619fe9118c1cf85070caf52ecdfe427a2e536e5f673cad`. It passes that image directly to the pinned upstream worker, avoiding the original-ROM path. The page has no audio controls, audio context, samples, or worker audio-enable message; its player starts silent. `scripts/test-open-swarm-browser-probe.mjs` serves the pinned checkout and local probe on a temporary loopback server with the cross-origin-isolation headers required by SharedArrayBuffer, blocks nonlocal requests, launches headless Edge with `--mute-audio`, then closes the browser and server. Run it after generating the draft and applying the edge patch using `node scripts/test-open-swarm-browser-probe.mjs`. The first run reported worker ready, 240 rendered frames, 474 nonblack display pixels, no page errors, and no audio enabled after synthetic Coin/Start/Fire/Right key events. This establishes a real browser worker/data/frame/input-*dispatch* path. It does **not** establish that the inputs changed game state, that the visuals are acceptable, or that a player can complete a wave in a browser. No release gate is claimed and the probe is not linked or deployed on the site.
