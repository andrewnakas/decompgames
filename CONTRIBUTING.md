# Contributing

Suggest a game through a GitHub issue or submit a pull request editing its catalog record. Include the canonical source project, engine license, asset terms, required edition/files, and links supporting your claims.

Keep project categories separate from play availability. Emulated games do not count as decompilations. Restricted source-available engines can be directory entries but cannot be hosted under this project's open-source-engine policy.

## Verification

An integration is not verified by its title screen. Record browser and OS versions, exact package revision, input, audio, representative play, in-game save, reload in a new session, and export/import results. Keep full-content availability separate from full-playthrough verification.

Test rejected files, cancelled import, malformed archives, storage failure, and save migration. Check network requests: no imported bytes may leave the device. Do not attach commercial game data to issues or pull requests.

## Runtime releases

Pin the upstream commit and compiler. Retain every upstream license and any dependency notices. Include build scripts, patches, checksums, and the corresponding source archive alongside the binary. A link to a moving branch is insufficient. Increment the package revision for every binary change, and the save compatibility version when needed. Retain previous releases for rollback.

## Content

Write useful original requirements, controls, known issues, and observations. Do not invent tests, screenshots, license permissions, rankings, keyword volumes, or traffic projections. Keep downloaded screenshots tied to an attribution and usage-rights record.
